## 修复：跳跃/下滑后跑步动画不恢复

- 现象：开始游戏不播放跑步、跳/滑后跑步动作消失，偶尔又能跑。
- 根因：`Player.stand()` 用 `if (this.anims.currentAnim?.key !== 'run')` 判断是否重播。
  Phaser 的 `anims.stop()` 之后 `currentAnim.key` **仍保留为 'run'**（只是暂停），
  所以落地后该判断为 false，跳过 `play('run')`，而此时纹理早已被切成 `jump`/`slide`
  并冻结 → 跑步动画永远回不来。第一帧若未踩地触发 `jump()` 也会陷入同样死锁。
- 修复：用 `this.mode` 状态机（'run'|'jump'|'slide'）。状态切换时才重设纹理/碰撞体；
  `stand()` 始终调用 `this.anims.play('run', true)`（ignoreIfPlaying 为 true 时，
  若已在播则无缝续播，若被 stop 则自动重启），不再依赖 currentAnim.key 判断。
- 复用要点：**不要用 `currentAnim.key` 决定是否 play 动画**，stop 后 key 不变；
  用 mode/状态标志或直接 `play(key, true)` 即可。

## 修复：高分屏文字模糊（DPR）

- 现象：铺满手机后文字发虚。根因：Phaser 4 `ScaleManager` **不会**按 `devicePixelRatio` 放大画布内部分辨率（源码 `canvas.width = baseSize.width`，baseSize=gameSize，无 DPR 乘子）。
  画布内部只等于 CSS 像素数，而手机物理像素是 2~3 倍，浏览器把整张画布放大渲染 → 文字/图形发虚。
- 修复（不动任何布局/物理数值，坐标仍用 CSS 单位）：
  1. `config.js` 新增 `DPR = min(devicePixelRatio, 2)`（上限 2 兼顾性能）。
  2. `main.js` 画布内部分辨率 `width: GAME_WIDTH*DPR, height: GAME_HEIGHT*DPR`（高清渲染）。
  3. `MenuScene`/`GameScene` 的 `create()` 加：
     `this.cameras.main.setZoom(DPR); this.cameras.main.centerOn(GAME_WIDTH/2, GAME_HEIGHT/2);`
     —— 经源码确认相机公式 `worldView.x = scrollX + width/2 - (width/zoom)/2`：zoom=DPR + centerOn 世界中心
     可使可见区精确落在 (0,0)-(GAME_WIDTH,GAME_HEIGHT)，文字按 DPR 重渲染变清晰。
     （注意：若只用 `setZoom(1/DPR)` 方向写反，画面会缩小并偏移，必须 DPR + centerOn。）
- 说明：位图精灵（run/obs/ground 等）本身仍是原分辨率、被相机放大 DPR 倍，清晰度与改动前一致（改动前是整个 CSS 画布被浏览器放大 DPR 倍，精灵同样软）；本修复主要消除**文字**模糊（文字是矢量重渲染到高清画布）。
  若要精灵也像素级清晰，需提供更高清素材或把各精灵 display scale ×DPR（改动较大，本次未做）。
- 验证：`npm run build` 通过；相机变换数值校验（DPR=2,W=390）worldView=(0,0)-(390,844) 正确；dev server 5178 模块均 200。

## 修复：竖屏旋转后点击「只会跳跃」+ 结算文字看不见

- 用户反馈两个 bug：① 竖屏时按钮点击只会跳跃（点哪都跳）；② 游戏结束后的文字看不见。
- **根因①（输入映射被破坏）**：Phaser 的输入坐标由 `ScaleManager.transformX/Y` 用 `canvas.getBoundingClientRect()` 做「轴对齐矩形」映射。竖屏时对 canvas 做了 `rotate(90deg) scale(cover)` 的 CSS 变换，导致屏幕 X/Y 互换，点哪都映射到错误游戏坐标 → 按钮 `over` 命中失败 → 全局 `pointerdown` 直接 `tryJump()`，于是「只会跳跃」。
  - **修复（关键）**：单靠 `transformX/transformY`（各只收一个坐标）无法纠正旋转，必须在拿到完整 `(pageX,pageY)` 处统一反旋转。故**重写 `game.input.transformPointer`**（`main.js` 的 `installInputTransform()`）：
    - 旋转时：`lx=(pageY-cy)/cover; ly=-(pageX-cx)/cover; x=(lx/dW+0.5)*baseW; y=(ly/dH+0.5)*baseH`（baseW/H = GAME_WIDTH/HEIGHT*DPR）。
    - 未旋转时：走官方默认（`canvasBounds` + `displayScale`）。
  - `applyOrientation()` 把 `cover/dW/dH/cx/cy` 写入共享 `orient` 对象，resize/orientationchange 时刷新；override 在 `game.events.once('ready')` 安装。
  - **数值验证（DPR=2, 竖屏 390×844）**：点滑铲按钮屏幕位 (~70,69) 正好还原为游戏内 (70,320) 命中按钮；屏幕顶/底/左/右分别映射到游戏 (0,GH/2)/(GW,GH/2)/(GW/2,GH)/(GW/2,0)，全部正确。
- **根因②（文字越界）**：结算文字 y=380/470/540/660 与 MenuScene 的 y=560/720 都是按**旧竖屏 960 高**写死的，现在 `GAME_HEIGHT≈390`（横版短边），全在画面外 → 看不见。
