## 修复：AI 生成素材没有透明通道（白底方块）

用户反馈"需要处理图片透明背景"。

### 根因

`ImageGen` 传了 `background=transparent`，但产出的 6 张 PNG 的 IHDR **colorType=2（RGB，无 alpha 通道）**，放进游戏是一整块白底方块。上一轮我用 Read 看图判断"透明背景生效"是**误判**（白色渲染出来看着像透明）。

> 教训：判断 PNG 是否真透明，读 IHDR 第 25 字节（colorType：2=RGB，6=RGBA），不要靠肉眼看图。

### 处理流水线（`tools/make_alpha.py`）

原图备份在 `.orig_assets/`（脚本的**输入源**，不要删）。

1. **背景检测**：多阈值扫描（250→174，步长 3），每轮用 `ndimage.label` 取**与画布边界连通**的低饱和近白区域作为背景；面积超过 82% 护栏就停止（防止吞并物体）。只取触边连通域，物体内部高光不会被误删。
2. **形态学清理**：`binary_fill_holes` 填孔洞 + 去掉 <0.1% 面积的孤立噪点。
3. **软边**：alpha 做 1px 高斯模糊。
4. **去白边（关键）**：`distance_transform_edt(return_indices=True)` 做**颜色外推** —— 先 `binary_erosion` 出实体核心，再把核心之外所有像素的颜色替换为最近实体像素的颜色。比 premultiplied 均值滤波彻底得多（钻石 halo 从 10.3% → 0%）。
   - **细结构保护**：引线、火花这类 1~3px 宽的结构会被侵蚀抹掉，若也外推会把颜色污染成邻近主体色。用邻域 solid 计数（<6 判为细结构）保留原色。TNT halo 因此从 13.2% 降到 7.8%。
5. **紧致裁切**到内容 bbox + 2% padding。
6. **降采样**到长边 256（游戏内最大显示 84px，3 倍超采样足够）。因为透明区颜色已外推成物体色，**非预乘缩放也不会混入白边**。

结果：6 张全部 RGBA，体积 5.9MB → 442KB（-93%），尺寸变为 `miner 193x256 / gold 256x201 / diamond 235x256 / rock 256x251 / bag 238x256 / tnt 231x256`。

QA 脚本 `tools/qa_alpha.py`：四角 alpha=0、边界 3px alpha<0.02、halo（亮且低饱和的边缘像素占比）<10%、物体未被原画布裁切。6/6 全过。

## 修复：Phaser 版画面太糊（高清屏发虚）

用户反馈"phaser 版本画面太糊"。

### 根因

之前 `fitCamera()` 用 `Scale.FIT` 思路（实际已切 `Scale.NONE` 但核心逻辑没改）：把画布物理像素设成 `dispW = W*s`（**CSS 像素，没乘 DPR**），再由 `cam.setZoom(s)` 放大世界内容。在 DPR=2 的视网膜屏上，backing store 仍是 CSS 像素量级，浏览器再放大 2 倍 → 双线性插值发虚。

> Phaser 4 已移除 GameConfig 顶层 `resolution` 与 `autoDensity`（grep 确认 GameConfig 91298~91560 范围无 `resolution` 字段；仅 `Phaser.Types.GameObjects.Text.TextStyle` 与 `RenderConfig` 内有 `resolution`）。所以高清屏只能手动 DPR 处理。

### 修复（`src/phaser/GameScene.ts` 的 `fitCamera()`）

1. 新增 DPR 维度：`s` = contain 适配比例（CSS 像素）；`cssW=W*s, cssH=H*s`（逻辑显示尺寸）；`devW=round(cssW*DPR), devH=round(cssH*DPR)`（物理像素）。
2. `this.scale.setGameSize(devW, devH)` —— backing store 设到设备像素。
3. **关键**：NONE 模式下 Phaser 会把 `canvas.style` 设为设备像素尺寸，这里手动改回 `canvas.style.width/height = cssW/cssH px`，使每个 CSS 像素对应 DPR 个物理像素。
4. `cam.setZoom(devW / W)`（= s*DPR）让世界 W 单位填满 devW 物理像素 = cssW CSS 像素。
5. 文字纹理分辨率 `setResolution(devW / W)`（上限 3），相机放大后文字不再发虚。
6. 素材长边已从 256 提至 512（`tools/make_alpha.py` 的 `MAX_EDGE=512`），游戏内最大显示 84px，超采样充足。

`DPR = min(devicePixelRatio, 2)`（`GameScene.ts` 顶部常量，>2 收益极小但显存线性涨）。

### 验证（无头，11/11 通过，无截图）

`playwright-core` + 系统 chrome，`deviceScaleFactor:2`、`viewport 1280x800` 模拟视网膜屏：

- 物理像素 = 2560×1600（CSS 1280×800 × DPR 2）✓
- canvas CSS 尺寸 = 1280×800（逻辑）✓
- 每 CSS 像素对应 2 物理像素（pxPerCss=2.0=dpr）✓
- `zoom = 2.667`（= devW/960）✓
- 矿工 385×512 / 金块 512×401（长边均 512）✓
- 0 console error（favicon 404 已排除）✓
