# 2026-09-03

## 修复：PC 端游戏画面未居中

**根因（源码级）**：`styles.css` 的 `#game { display: grid; place-items: center }` 已经把 canvas 居中了一次；
同时 `createCatchGame.ts` 里 Phaser 配了 `scale.autoCenter = CENTER_BOTH`，Phaser 的
`ScaleManager.updateCenter()`（node_modules/phaser/src/scale/ScaleManager.js:1208）会再通过
`canvas.style.marginLeft/marginTop` 居中一次。两套机制叠加：
grid 居中「canvas + margin」整体后再被 margin 推走，最终偏移量为正确值的 1.5 倍
（净多偏 `(P-W)/4`）。移动端因某个方向 `parentSize ≈ canvasSize` 偏移接近 0，所以只有 PC 宽屏才暴露。

**修复**：
- `src/game/createCatchGame.ts`：`scale.mode` 改 `Phaser.Scale.NONE`，`autoCenter` 改 `Phaser.Scale.NO_CENTER`。
  职责划分：Phaser 只管渲染分辨率（canvas.width/height = 390×RENDER_SCALE），CSS 管显示尺寸与居中。
- `src/styles.css`：canvas 加 `margin: 0 !important` 兜底；width/height 补 `vh/vw` fallback 后再写 `svh/svw`；加了 `border-radius: 18px` 适配 PC。

**关键结论（复用价值高）**：
- Phaser 的 `displayScale = baseSize / canvasBounds`，而 `canvasBounds` 来自 `getBoundingClientRect()`。
  所以用 CSS `!important` 覆盖 canvas 显示尺寸**不会**导致输入坐标错位，可以放心让 CSS 接管尺寸。
- `SCALE_MODE.NONE` 且 `zoom === 1` 时 Phaser 完全不写 canvas inline style（`_resetZoom` 保持 false）。
- 场景 `CatchGameScene` 用逻辑坐标 390×844 + `camera.setZoom(RENDER_SCALE)` 布局，不依赖 ScaleManager 尺寸，
  所以切换 scale.mode 是安全的。
